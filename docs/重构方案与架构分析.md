## 1. 项目结构

全站只有两个路由根，且**没有任何懒加载**（`app.module.ts` 直接 `imports: [PortalModule, AdminModule]`）：

- `/admin` —— 管理端，约 100 条子路由，父组件 `AdminComponent` + `AdminAuthCheckGuard`
- `/portal` —— 普通用户端，27 条子路由
- `/portal/.../terminal/...`、`/portal/logging/...` —— pod 终端与日志，路径极长且参数多
- `/sign-in` —— 登录
- `/` 重定向到 `admin/reportform/overview`

分层：

```
src/app/shared/client/v1/     70+ 个 HTTP service（+ kubernetes/ 子目录 19 个专用 client）
src/app/shared/model/v1/      数据模型
src/app/shared/base/          页面基类（见 §3.3，是重复问题的核心）
src/app/{admin,portal}/       各功能目录：xxx.component + create-edit-xxx + list-xxx + trash-xxx
lib/                          插件式独立目录（service / servicetpl），同样参与编译
```

## 2. 首要发现：HEAD 编译不过

`src/app/shared/auth-module/sign-in/sign-in.component.ts:47`：

```ts
if (this.authService.config?.oauth2Providers) {   // ← 可选链，TS 3.7+ 才支持
```

项目 `package.json` 锁定 `typescript: ~3.4.5`，构建直接报：

```
ERROR in app/shared/auth-module/sign-in/sign-in.component.ts:47:33
error TS1109: Expression expected.
```

这是最新一次提交（"feat: 登录页支持多 OAuth2 provider 按钮"）引入的。**任何后续工作都必须先修掉它，否则连基线都没有。**

修复方式为行为等价改写（`a?.b` 的真值判断 ≡ `a && a.b`）：

```ts
if (this.authService.config && this.authService.config.oauth2Providers) {
```

全仓可选链/空值合并仅此一处（已全量扫描确认）。

## 3. 架构问题清单（均带证据）

### 3.1 HTTP 客户端参数拼装重复 —— 已处理

45 个方法各自内联了同一套「分页 + 动态参数 + 过滤串 + 排序覆盖」逻辑，归一化后是 **33 种变体**。

证据（`tools/analyze-list-patterns.js` 输出，见 `contract/list-patterns.txt`）：

- 簇 1（6 个方法，完全同构）：`deployment/cronjob/secret/ingress/autoscale.service.ts` + `lib/.../service.service.ts`
- 簇 2/3/5/6/8：各 2 个方法两两同构
- 其余为单例变体

差异全部落在 5 个轴上，**不存在"看似重复实则语义不同"的隐藏分支**：

| 差异轴 | 取值示例 |
|---|---|
| 前置字面量 | `deleted`、`relate='all'`、`appId`、`sortby='-id'` |
| 动态参数来源 | `pageState.params`（多数） / `pageState.filters`（auditlog） |
| filter 精确键集 | `['deleted','id']`（多数） / `['id']`（config、customlink、roadmap） |
| sortby 排除字段 | 无 / `['app.name']` / `['app.name','user.name']` / `['service.name']` |
| 尾部追加 | `deleted='false'`（customlink、roadmap） |

> **重要反例**：`shared/client/v1/kubernetes/base-client.ts` 的 `buildParam()` 用的是 **全部 `key=value`** 的过滤语义，而 v1 业务 service 用的是 **`key__contains=value`**。两者面向不同后端（`_proxy` vs wayne API），**不能合并**——这正是"看起来能收敛、实则不能"的陷阱，本次刻意保留。

### 3.2 空转的错误处理 —— 已处理

325 处 `.catch(error => throwError(error))`。它把错误原样重抛，既不转换也不记录，在 rxjs-compat 下对消费者完全不可观测，**但会让人误以为这里有错误处理**。分布在 68 个文件。

保留的 5 个文件（非空转形态）：`app.module.ts`、`auth/{admin-auth-check-guard,auth-check-guard,auth}.service.ts`、`main.ts`。

### 3.3 两套平行基类，其中一套是死代码 —— 已处理

- `shared/base/kubernetes/`（`kubernetes-resource.ts`、`kubernetes-list-resource.ts`）
  → **全仓零引用**（已用 grep 严格验证：所有消费者 import 的都是 `kubernetes-namespaced/`）。已删除。
- `shared/base/resource/*`（portal 用）与 `shared/base/admin-resource/*`（仅 admin 的 autoscale/autoscaletpl 用）是两套并行的资源基类家族。

### 3.4 admin 侧大量复制粘贴（**未处理，建议下一批**）

admin v1 的页面（deployment/configmap/cluster/namespace/secret/ingress/cronjob/statefulset/daemonset/pvc/app/user/group/permission…）**不继承任何基类**，是同一份模板的 N 次复制：

| 文件 | 重复内容 |
|---|---|
| `admin/deployment/deployment.component.ts:39-111` | self-subscribe 删除确认、`retrieve()`、`openModal/delete/edit` |
| `admin/configmap/configmap.component.ts:36-103` | 与 deployment 100% 同构 |
| `admin/*/list-*/list-*.component.ts` | `pageSizeChange/refresh/delete/edit/goToLink` 逐方法对应 |

而 portal 侧同功能只需要 5 行：

```ts

  constructor(...) { super(...); this.registResource(new Deployment()); this.registResourceType('部署'); }
```

`goToLink` 这个硬拼 `/admin/${resourceType}/tpl?...` 的方法在 **11 个组件**里各写了一遍。

### 3.5 其它坏味道（未处理）

- **`any` 泛滥**：`src/app` 下 580 处，仅 `shared/base` 就 110 处。典型：`base/resource/resource.ts:48-54`、`:65-79`（基类构造函数注入 14 个 `any` 依赖）

## 4. 重构策略：怎么做到"可证明的兼容"

口号式的"完全兼容"没有意义。本次的做法是**先造尺子，再动手**，把兼容性变成可执行、可复现的断言。

### 4.1 三层验证资产

| 工具 | 作用 | 输出 |
|---|---|---|
| `tools/contract-snapshot.js` | 静态抽取对外契约：路由、HTTP 调用点（方法+URL 模板+查询参数键）、组件 selector | `contract/*.json` |
| `tools/check-contract.js` | 比对两份快照，任何差异即判定为破坏接口 | 退出码 0/1 |
| `tools/verify-param-equivalence.js` | 从旧源码**机械提取**原方法体并执行，与新实现逐字节比对 query string | 用例数 / 不一致数 |

### 4.2 参数等价性夹具的关键设计

三个要点让它比"人眼 review"可靠得多：

1. **零转录误差**：新旧两侧的方法体都由 AST 从源码提取，把结尾的 `return this.http...` 替换成 `return params;` 后用 `new Function` 还原执行。不存在"抄错一行"的可能。
2. **真的跑起来**：`@angular/common/http` 的 `HttpParams` 在 Node 下可直接 require，于是能真实比较 `params.toString()`，而不是比较源码文本。
3. **覆盖分支边界**：对每个方法按其入参名生成取值组合（`appId` 取 `undefined/''/'0'/'7'`，`deleted` 取 `undefined/'false'/'true'`），叠加 2×7×6×5 组 pageState（分页/排序/过滤/动态参数），共 93240 例。

> 夹具本身也做过对照实验：在**尚未改动任何 service** 时先跑一遍，确认"新旧相同"能判为一致、用例数非零。第一版夹具曾返回 0 个用例却打印"全部一致"——属于假绿，已修正。

### 4.3 为什么用 codemod 而不是手工改

38 个方法分布在 36 个文件，逐个手改既慢又易错。改为写 codemod（`tools/codemod-list-params.js`），由 AST 识别：
- 参数拼装语句区段（从 `let params = new HttpParams()` 到最后一个参数相关语句）
- 5 个差异轴的具体取值
- 区段内夹着的**非参数语句**（如 `if ((typeof(appId) === 'undefined')) appId = '0';`）——这些只影响 URL、不碰 params，**上提**到 helper 调用之前，不改变任何一次请求

正确性不由"codemod 看起来对"来保证，而是由 §4.2 的夹具兜底。

## 5. 已执行的改动明细

### 5.1 修复编译阻塞
- `shared/auth-module/sign-in/sign-in.component.ts:47` —— 可选链改为等价的 `&&` 判断

### 5.2 参数拼装收敛（核心改动）
- 新增 `src/app/shared/client/v1/list-params.ts` —— 全站唯一实现，固定内核 + 6 个显式差异轴
- 改写 36 个文件 / 38 个方法为对 `buildListParams()` 的调用

示例（`deployment.service.ts`，方法体 42 行 → 17 行）：

```ts
list(pageState: PageState, deleted?: string, appId?: string): Observable<any> {
  const params = buildListParams(pageState, {
    literals: [
      ['deleted', deleted],
      ['relate', 'all'],
      ['appId', appId + ''],
      ['sortby', '-id'],
    ],
    excludeSortby: ['app.name'],
  });

  if ((typeof (appId) === 'undefined') || (!appId)) {
    appId = '0';
  }
  return this.http.get(`/api/v1/apps/${appId}/deployments`, {params: params});
}
```

**刻意不收敛的 7 个方法**（语义不同，收敛会改变行为）：

| 方法 | 原因 |
|---|---|
| `app-user.service.ts::list` | switch 内既改 params 又给局部 `appId` 赋值 |
| `namespace-user.service.ts::list` | 同上，另有自定义 sortby 映射 |
| `webhook.service.ts::query` | `fromObject` 构造 + 反向 filter 语义（`name/url` 才 `__contains`）+ 顺带拼 URL |
| `kubernetes/base-client.ts::buildParam` | 面向 `_proxy` 的过滤语义，与 wayne API 约定不同 |
| `kubernetes/{job,event,pod}.ts` | 已基于 `BaseClient.buildParam` |

### 5.3 清理
- 删除死代码：`shared/base/kubernetes/`（2 个文件）
- 修复 `admin/admin.module.ts` 重复 import（`KubeJobModule`、`KubeNamespaceModule` 各出现两次）
- 修复 `shared/base/admin-resource/resource.ts:97` 模板串未求值 bug
  （`'你确认删除 ${this.componentName} '` 用了单引号，用户看到的是字面量 `${this.componentName}`；已改为反引号。**这是本次唯一的行为改动**，属于修 bug，如需保持原样请单独还原此文件）
- 移除 325 处空转 catch + 66 处随之失效的 `throwError` import

### 5.4 工程化
- 新增 `tools/` 下 6 个脚本（契约抽取/门禁、等价性夹具、两个 codemod、聚类分析、行尾归一化）
- `.gitignore` 增加 `contract/`（含旧源码树副本，不入库）
- 所有改动文件的行尾统一回仓库约定的 **CRLF**（脚本改写曾引入 LF，与本仓库 CRLF 混用；已用 `tools/normalize-eol.js` 归一，避免 diff 被行尾噪声淹没）
